# 工作流引擎项目规划 - 第二轮讨论

## 1. 对 architect_0.1 的评估与功能缺口

### 架构设计的优点
- 微服务架构清晰（5个核心服务）
- PostgreSQL 数据模型设计完整
- 技术选型合理（Java 17 + Spring Boot + Vert.x）
- 四个待讨论问题有初步方案

### 识别的功能缺口

| 缺失领域 | 具体问题 |
|----------|----------|
| 执行上下文 | 变量如何定义、传递、引用？无变量系统设计 |
| 节点类型系统 | 节点配置Schema、输入输出定义、调试能力缺失 |
| 触发器系统 | Webhook安全（签名/限流）、防重放机制未设计 |
| 版本管理 | Diff展示、回滚策略、灰度发布无方案 |
| 前端编辑器 | 架构完全缺失，编辑器如何设计？ |
| 监控运维 | 指标采集、告警规则、链路追踪未覆盖 |

## 2. 四个待讨论问题的功能影响分析

### 2.1 执行模式选择 → 功能规划

**方案B（异步队列+状态机）对功能的影响**：

| 功能 | 影响 | 规划要点 |
|------|------|----------|
| 执行控制 | 支持暂停/恢复/终止 | 需要提供执行控制API |
| 状态查看 | 实时状态推送 | WebSocket/SSE实时更新 |
| 故障恢复 | 从断点续传 | 保存执行上下文快照 |
| 超时控制 | 节点级超时设置 | 超时后自动重试或终止 |

**功能需求**：
- 执行控制API：暂停、恢复、终止、重试
- 执行状态实时推送
- 超时配置（节点级、流程级）

---

### 2.2 节点扩展机制 → 功能规划

**核心节点硬编码 + 插件预留接口**：

| 节点类型 | 功能需求 |
|----------|----------|
| 内置节点 | START, END, LLM, HTTP, CONDITION, PARALLEL, DELAY |
| 插件节点 | 用户上传JAR包，后端自动加载 |
| 节点市场 | 预置官方节点模板，用户可安装 |

**功能需求**：
- 节点注册中心（管理所有可用节点）
- 节点配置UI（动态表单生成）
- 节点分类与搜索
- 节点文档和示例

---

### 2.3 分支处理 → 功能规划

**条件分支 + 并行分支**：

| 场景 | 用户操作 | 功能需求 |
|------|----------|----------|
| IF/ELSE | 定义条件表达式 | 条件表达式编辑器（可视化） |
| 并行 | 设置并发数、超时 | 并行配置面板 |
| JOIN | 设置等待策略 | 合并策略选择（全部完成/任一完成/超时） |

**功能需求**：
- 条件表达式编辑器（下拉选择变量 + 比较运算符 + 值输入）
- 并行分支可视化展示
- 分支超时配置
- 合并策略选择

---

### 2.4 LLM集成 → 功能规划

**内置LLM节点 + 通用HTTP节点**：

| 功能 | 详细需求 |
|------|----------|
| 模型选择 | 下拉选择：OpenAI, Anthropic, Ollama, 自定义API |
| 参数配置 | temperature, max_tokens, system prompt |
| 提示词模板 | 变量替换、循环、条件（Mustache/Handlebars风格） |
| 响应处理 | JSON解析、字段提取、错误处理 |
| 对话历史 | 支持多轮对话上下文 |

**功能需求**：
- LLM节点配置面板
- 提示词模板编辑器（支持变量高亮、预览）
- 模型密钥管理（加密存储）
- 用量统计和成本追踪

## 4. 新增实现挑战

### 4.1 异步执行状态一致性

**挑战**：分布式环境下的状态同步

**问题**：
- Redis状态与PostgreSQL如何保证最终一致？
- Worker进程crash后状态如何恢复？
- 并发更新同一执行如何处理？

**建议方案**：
- 乐观锁（版本号）防止并发冲突
- 事件溯源（Event Sourcing）记录状态变更
- 定期checkpoint保存到数据库

---

### 4.2 条件表达式性能

**挑战**：高频执行下的表达式解析

**问题**：
- 每次执行都解析表达式开销大
- 复杂表达式计算耗时
- 表达式注入安全风险

**建议方案**：
- 表达式预编译（编译成执行码）
- 变量值缓存（避免重复获取）
- 沙箱执行（限制函数和操作）

---

### 4.3 并行分支调度

**挑战**：分布式环境下的并行协调

**问题**：
- 如何感知所有分支完成？
- 分支失败如何传播？
- 资源竞争如何处理？

**建议方案**：
- Redis分布式锁协调
- 分支状态聚合器
- 超时检测机制

---

### 4.4 插件安全隔离

**挑战**：用户自定义代码的安全运行

**问题**：
- 插件可能执行恶意代码
- 插件可能无限循环
- 插件可能消耗过多资源

**建议方案**：
- V1：JAR包审核 + 线程池隔离
- V2：沙箱执行（WebAssembly/Docker）
- 资源限制（CPU/内存/超时）

---

### 4.5 流程图大规模渲染

**挑战**：复杂流程的编辑器性能

**问题**：
- 100+节点渲染卡顿
- 缩放/平移操作不流畅
- 节点定位算法效率

**建议方案**：
- 虚拟化渲染（只渲染视口内节点）
- Canvas分层（背景/连线/节点）
- Web Worker处理布局计算
