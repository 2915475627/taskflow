# TaskFlow 开发流程

## 概述

本文档定义 TaskFlow 项目的标准开发流程，适用于前后端并行开发、测试驱动开发（TDD）和端到端（E2E）测试。

**技术栈：**
- 后端：Spring Boot 3.2.4 + Java 17 + JPA + PostgreSQL
- 前端：React + Vite + TypeScript + React Flow + Zustand + Playwright

---

## 阶段一：环境验证与功能设计

### 1.1 服务可用性检查

```bash
# 1. 检查 Docker 服务
docker ps | grep -E "postgres|redis"

# 2. 检查后端 (端口 8080)
curl -s http://localhost:8080/api/workflows -H "X-Tenant-ID: 1" || echo "Backend down"

# 3. 检查前端 (端口 5173)
curl -s http://localhost:5173 | head -5 || echo "Frontend down"

# 4. 检查 PostgreSQL 连接
docker exec -it taskflow-postgres psql -U taskflow -d taskflow -c "SELECT 1"
```

### 1.2 启动服务（如需）

```bash
# 后端
cd backend && mvn spring-boot:run > /tmp/backend.log 2>&1 &

# 前端
cd frontend && npm run dev > /tmp/frontend.log 2>&1 &
```

### 1.3 功能设计与任务分解

**使用 Agent：**

| Agent | 用途 |
|-------|------|
| `planner` | 分解功能为前后端任务 |
| `architect` | 评估技术方案和依赖 |

**输出：**
- [ ] 功能列表（后端 API + 前端组件）
- [ ] 任务优先级排序
- [ ] 明确本次迭代范围（至少实现一个大功能）

## 阶段二：并行开发

### 2.1 后端开发流程

**使用 Agent：**

| Agent | Skill | 用途 |
|-------|-------|------|
| `tdd-guide` | `springboot-tdd` | TDD 流程指导 |
| `go-reviewer` | - | 代码审查 |

**流程：**

```
┌─────────────────────────────────────────────────────────┐
│  1. 功能分析 & 测试计划                                   │
│     - 分析 API 接口需求                                   │
│     - 使用 tdd-guide 规划测试用例                         │
│     - 输出: API 设计文档 + 测试用例清单                    │
└─────────────────────────────────────────────────────────┘
                            ↓
┌─────────────────────────────────────────────────────────┐
│  2. 编写单元测试 (RED)                                   │
│     - 编写失败的单元测试                                   │
│     - 验证测试正确性                                      │
└─────────────────────────────────────────────────────────┘
                            ↓
┌─────────────────────────────────────────────────────────┐
│  3. 实现功能代码 (GREEN)                                 │
│     - 编写最小实现使测试通过                               │
│     - 遵循 springboot-patterns                           │
└─────────────────────────────────────────────────────────┘
                            ↓
┌─────────────────────────────────────────────────────────┐
│  4. 重构 (IMPROVE)                                      │
│     - 使用 go-reviewer 审查代码                          │
│     - 清理重复代码                                       │
│     - 更新文档                                           │
└─────────────────────────────────────────────────────────┘
                            ↓
┌─────────────────────────────────────────────────────────┐
│  5. 验证测试覆盖率 ≥ 80%                                 │
│     mvn test -Djacoco                           │
└─────────────────────────────────────────────────────────┘
```

**后端产出文档：**
- [ ] `docs/backend/API 设计.md` - API 接口规范
- [ ] `docs/backend/TEST_CASES.md` - 测试用例清单
- [ ] `docs/backend/COVERAGE.md` - 覆盖率报告

### 2.2 前端开发流程

**使用 Agent：**

| Agent | Skill | 用途 |
|-------|-------|------|
| `frontend-design` | `frontend-patterns` | 前端开发指导 |
| `e2e-runner` | `e2e` | E2E 测试 |

**流程：**

```
┌─────────────────────────────────────────────────────────┐
│  1. 功能分析 & 测试计划                                   │
│     - 分析组件需求                                        │
│     - 规划组件测试                                        │
│     - 输出: 组件设计文档 + 测试用例清单                    │
└─────────────────────────────────────────────────────────┘
                            ↓
┌─────────────────────────────────────────────────────────┐
│  2. 编写组件测试 (RED)                                   │
│     - 编写失败的 Vitest 单元测试                          │
│     - 验证测试正确性                                      │
└─────────────────────────────────────────────────────────┘
                            ↓
┌─────────────────────────────────────────────────────────┐
│  3. 实现组件代码 (GREEN)                                 │
│     - 使用 frontend-patterns                             │
│     - 遵循组件设计规范                                    │
└─────────────────────────────────────────────────────────┘
                            ↓
┌─────────────────────────────────────────────────────────┐
│  4. 重构 & 代码审查                                      │
│     - 清理重复代码                                       │
│     - 确保组件可复用                                     │
└─────────────────────────────────────────────────────────┘
                            ↓
┌─────────────────────────────────────────────────────────┐
│  5. 验证测试覆盖率 ≥ 80%                                 │
│     npm run test:coverage                        │
└─────────────────────────────────────────────────────────┘
```

**前端产出文档：**
- [ ] `docs/frontend/COMPONENT_DESIGN.md` - 组件设计
- [ ] `docs/frontend/TEST_CASES.md` - 测试用例清单

## 阶段三：联调与 E2E 测试

### 3.1 TDD 联调流程

**前后端同时进行：**

```bash
# 1. 后端启动（已验证功能）
cd backend && mvn spring-boot:run

# 2. 前端启动（API 集成）
cd frontend && npm run dev
```

**使用 Agent：**

| Agent | 用途 |
|-------|------|
| `tdd-guide` | 指导 API 集成测试 |
| `e2e-runner` | 执行 Playwright E2E 测试 |

**联调步骤：**

```
┌─────────────────────────────────────────────────────────┐
│  1. 编写集成测试                                          │
│     - 后端: 使用 MockMvc 测试 API                         │
│     - 前端: 使用 MSW 模拟 API 响应                        │
└─────────────────────────────────────────────────────────┘
                            ↓
┌─────────────────────────────────────────────────────────┐
│  2. 真实 API 联调                                        │
│     - 后端 Controller 测试                               │
│     - 前端 API Service 测试                             │
└─────────────────────────────────────────────────────────┘
                            ↓
┌─────────────────────────────────────────────────────────┐
│  3. 问题修复                                              │
│     - 使用 build-error-resolver 修复构建错误             │
│     - 使用 tdd-guide 修复测试问题                        │
└─────────────────────────────────────────────────────────┘
```

### 3.2 E2E 浏览器测试

**使用 Agent：`e2e-runner`**

```bash
# 运行 Playwright E2E
cd frontend && npx playwright test

# 生成测试报告
npx playwright show-report
```

**E2E 测试用例：**

| 用例 | 描述 |
|------|------|
| `workflow-create.spec.ts` | 创建工作流 |
| `workflow-edit.spec.ts` | 编辑工作流 |
| `workflow-execute.spec.ts` | 执行工作流 |
| `workflow-delete.spec.ts` | 删除工作流 |

### 3.3 测试报告产出

**产出：**
- [ ] `docs/TEST_REPORT.md` - 完整测试报告
- [ ] `docs/E2E_REPORT.md` - E2E 测试报告
- [ ] Playwright 报告 `frontend/playwright-report/index.html`
